# 교훈 (lessons)

## 2026-06-11 (사용자 피드백)

- **글 못 읽는 유아용 앱은 모든 상태 변화에 음성 안내가 따라야 한다.**
  - 사례: 레벨 시작에만 "하나! 어디 있을까?"를 말하고 이후엔 화면 숫자만 갱신 → 아이 입장에선 "같은 숫자 맞추기"가 됨. 실제 사용해본 아빠가 바로 발견.
  - 규칙: 유아용 UI를 설계할 때 "화면만 바뀌고 소리가 없는 순간"이 있는지 시나리오 전체를 음성 관점에서 점검할 것. 안내 문구는 "숫자! 찾아보세요. 숫자!"처럼 핵심 단어를 앞뒤로 반복.

## 2026-06-11

- **계획서에 적은 테스트 코드의 단언(assert)이 약하면, 구현 단계에서 그대로 복사된다.**
  - 사례: `shuffledNumbers` 난수 주입 테스트가 length만 검사 → 주입이 무시돼도 통과하는 무의미한 테스트가 됨.
  - 규칙: 계획서에 테스트 코드를 쓸 때 "이 테스트가 잘못된 구현을 실제로 잡아내는가?"를 자문할 것. 결정적(deterministic) 출력을 단언할 수 있으면 그렇게 쓸 것.

- **`node --test <디렉터리>` 방식은 Node 24에서 깨진다.**
  - 사례: `"test": "node --test tests/"`가 MODULE_NOT_FOUND로 실패. 인자 없는 `node --test`가 기본 글롭(`tests/*.test.js`)으로 동작.
  - 규칙: 계획서에 명령어를 쓸 때 실행 환경(Node 메이저 버전)별 동작 차이를 의심하고, 가장 보수적인 형태를 쓸 것.
